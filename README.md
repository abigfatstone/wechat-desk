# 微信工作台 · 0.2.0

独立市场插件。零点账号服务端不接入微信。微信只绑定一个入口；在零点里查询与从微信提问使用同一套只读查询代码。

## 从零点使用

1. 本机安装 Node.js 22 或更新版本，准备好可用模型的零点桌面 workspace。解压项目。在「设置 → 插件 → 插件」添加 **`plugins/wechat-desk` 的本机绝对路径**；也可以用根目录添加自定义市场后安装「微信工作台」。
2. 在目标 workspace 会话输入 **`/wechat-desk-setup`** 获取已安装版本的本机设置命令。用该 workspace 目录作为工作目录，在本机终端运行设置向导，选 `zero`。市场安装不等于资料授权。不要将生成的 `.opencode/plugins/wechat-desk/index.ts` 提交到共享仓库，它指向本机安装位置。
3. 任选一个历史源：① **已有且已授权的 tzwkb 只读查询环境**，选择项目和 Python 解释器，一次设置后直接按需查询，不用每次重新导出；本插件不安装上游、不获取密钥、不刷新 Windows 明文镜像，数据新鲜程度取决于已有源。② **导入目录**，每次查询重新读取目录内的 TXT、MD、JSONL 文件。JSONL 每行示例：`{"chat":"项目群","time":"2026-11-24T09:00:00+08:00","sender":"同事","text":"周五已确认"}`。没有日期的纯文本不能可靠回答「昨天」的问题。
4. 选择是否配置目标 workspace 别名、是否扫码绑定。二维码和 PIN 只在本机终端交互；在另一台机器上重新绑定同一微信可能断开旧入口。打开/重新加载这个 workspace 后开始接收。可只授权查询，稍后再扫码。
5. 在微信 ClawBot 或该 workspace 询问：「查项目群最近两天的交付日期，标出谁确认过，给我一句回复草稿。」微信通道接收文本和自带转写的语音。结果和草稿回到本人 ClawBot；不会以个人微信身份给原群发消息。

### 工作区协作

只给入口配置用户选定目标的别名和零点 Agent UUID（目标必须可由入口通过已有 A2A 联系）。微信发送 `@乙 起草一份安排`，入口展示目标和实际转发的文本。5 分钟内回复 `1` 提交一次，`2` 取消。转发不附源数据库、凭据或历史；每次最多一个进行中的任务。可以发「任务进度」。入口在线时会检查已提交任务并尝试送回最终结果；无法确认送达时不反复重发。远端工具的权限仍由目标 workspace 本身决定，`1` 只批准转发。

### 宿主、权限与数据

- 零点插件安装是账号级；设置向导写入本机用户目录下、按 workspace 的规范路径派生的授权，以及该项目的本地 OpenCode 适配入口。查询时再次比对宿主和会话目录，调用参数不能选任意目录或命令。市场关闭后，通过已安装路径配置的查询和新投递会被拒绝；重新启用后重新加载 workspace。这是插件级授权，不是同一系统用户下多个进程的文件系统沙箱。
- 微信绑定、游标和去重状态在本机 `~/.zero-wechat-desk/` 下，Windows 使用当前用户的 home。凭据是本机文件，不是系统钥匙串；依赖本机账号访问控制。命中片段会进入 workspace 配置的模型；用远程模型时，不应理解为推理也在本机。微信问答另存在本 workspace 的「微信工作台」会话里。
- `setup.mjs status` 显示资料源、绑定与最近投递状态。`submitted` 只表示接口接受，不代表手机已读。`-14` 后停止拉取，提示重新绑定。`setup.mjs disable` 撤销权限、删除本机绑定和接收进度；不删除用户的资料源或既有零点会话。若进程异常退出留下锁，`setup.mjs unlock` 仅在原进程已退出时清理，再重新加载 workspace。
- OpenClaw 模式：安装本目录作为本地 OpenClaw 插件（`openclaw plugins install <本目录绝对路径>`），由官方微信渠道负责扫码和收发。在 OpenClaw agent 的实际 workspace 目录执行设置向导，选择 `openclaw` 并填写本人渠道 sender ID。只为宿主识别出的本人微信私聊提供 `wechat_history_query`。宿主如采用工具白名单，需要允许该工具。不要同时开两个微信接收端。零点 A2A 委派只在零点入口使用。
- 三种桌面平台共用 JS，不分发依赖架构的微信数据库程序。只读查询适配调用用户已有的 [tzwkb/wechat-decrypt](https://github.com/tzwkb/wechat-decrypt) 查询 CLI；只允许 list/read/search/recent/summary/events，不运行上游安装、提权或提取脚本。微信和宿主实际版本需分别验证。

## 开发与验收

`node --test test/desk.test.mjs` 使用合成数据。`PYTHON` 可以指定测试用解释器；CI 配置 Windows、Apple Silicon Mac、Intel Mac 三个作业。测试覆盖扫码响应、端到端模拟、重放、撤销、只读子进程和委派确认。二维码渲染使用 qrcode-terminal 0.12.0，其声明见插件的 `vendor/`。本包未发布到公共市场。

### 历史版本 0.1.0（不再作为市场主入口）

独立的零点能力包项目，版本 0.1.0。不依赖零点源码，不包含上游密钥提取程序，不连接微信或读取微信数据库。当前实现是对文本进行逐行关键词搜索，无需构建；要求目标设备的 PATH 中有 Node.js 18+。

## 安装和使用

1. 解压整个项目。在零点「设置 → 插件 → 插件」添加本机 `plugins/wechat-history` 的绝对路径，预览并安装；也可将项目根目录作为自定义市场来源。
2. 在要使用的工作区创建 `wechat-import`，把自己选定的 UTF-8 TXT、Markdown 或 JSONL 聊天导出放进去。可使用已有导出，不要求特定导出工具。单文件上限 16 MiB，不递归，不跟随链接。
3. 在该工作区新会话中输入 `/wechat-history-wechat-search 合同`。返回文件、行号和匹配片段；搜索不区分大小写。JSONL 按原文逐行检索，不解析消息结构。

插件安装属于账号级配置；不同工作区的导入目录各自独立，这是数据组织约定，并非工作区访问控制。查询脚本不联网，返回给会话的片段会进入当前模型上下文。没有系统级依赖安装、常驻监听或后台同步。

## 范围

本版独立实现，没有复制 tzwkb/wechat-decrypt 源码。上游的只读查询层可作为以后适配已授权数据源的候选。Windows、Apple Silicon Mac、Intel Mac 共用同一份 JavaScript；三端零点客户端仍需分别验收。独立项目不等于已发布到公共插件市场。
